# GPU marketplace photo sourcing

Reviewed 2026-11-22 for [#53](https://github.com/OmniMCP-AI/local-llm/issues/53). Marketplace listings are discovery evidence and temporary listing views, not a permission to reproduce a seller's photograph in a permanent gallery. No Amazon Creators API or eBay Browse API credentials or approved display integration were available in this checkout. No live feed, listing display, image bytes, or new permanent photo coverage is claimed by this change.

## Editor workflow

1. Search using the catalog identity **and full board part number**, then inspect the actual Amazon child ASIN/variation or eBay item and selected variant. Record the item, variant, listing URL, exact catalog ID and part number, and independent evidence connecting that listing variant and the pictured image to that board. Similar model names, 8/16 GB variants, OC versus non-OC SKUs, and shared stock imagery are not interchangeable. If the source does not establish the exact variant, retain a source lead only.
2. Classify the specific image as `seller-specimen` only when its origin and relationship to the listed specimen are supported; otherwise classify confirmed reused manufacturer/catalog imagery as `product-imagery`. Unknown classification is not an eligible exact view. A product image does not prove condition or modifications to a specimen.
3. Obtain approved provider access and review all applicable provider rules for the market and application before enabling any public listing display. The small `listingPhoto` projection in `marketplace-photos.mjs` is a fail-closed input boundary for a future live integration, not an API client or proof of compliance. Its `reviewedPartNumber`, `reviewedVariantId`, `matchEvidence`, and `imageEvidence` are editor-reviewed evidence; an automated caller must not populate those fields from the listing alone. `approvedProviderAccess` is an operational attestation, not a substitute for a grant. The call must receive fresh provider data and be made again for every display; never cache its output in a release. On provider withdrawal, listing removal, loss of public access, refresh failure, or expiry, discard the reference immediately. The conservative expiry limit is 24 hours for both providers; a shorter provider or integration requirement takes precedence. eBay requires removal when the content is no longer public, which may happen sooner than expiry. A real integration must actively enforce removal and provider display/linking rules; merely calling this projection once cannot do that.
4. Keep live results in a provider-specific listing area linking to the exact listing. eBay's API license requires public eBay content to be visually isolated from third-party listings or other non-eBay information. Amazon requires applicable Special Links and attribution. This change does not implement or authorize that UI. Amazon Associates policy permits an image link cache of at most 24 hours and prohibits storing the program image itself. See [Amazon policies](https://affiliate-program.amazon.com/help/operating/policies), [Amazon image resources](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/api-reference/resources/images), [eBay API license](https://developer.ebay.com/support/api-license-agreement), and [eBay Browse API](https://developer.ebay.com/api-docs/buy/browse/resources/item/methods/getItem).
5. A permanent gallery photo requires a **separate durable grant** for the particular image, exact identity, intended storage, adaptation and redistribution. Review and ingest it through the existing catalog media registry and withdrawal process; provider display permission alone is insufficient. Only an independently approved exact photo counts toward permanent coverage. Static HTML and Markdown exports must not contain the provider image or live listing reference absent that separate review.

The projection expects UTC timestamps with a `Z` suffix, an explicit provider expiry, an active/public provider status, and approved access. Amazon item and variant IDs are ASINs and the listing URL must point to the child ASIN. eBay requires a numeric item ID and explicit reviewed variant identifier, even for a single-variant item (the integration should assign an unambiguous provider-derived identifier). Input is untrusted and rejected when evidence or identity is incomplete. The provider terms may require more than the checks performed here.

## Sourcing observations

- [eBay item 137016414155](https://www.ebay.com/itm/137016414155) was indexed with title `DUAL-RTX5060TI-16G - Dual GeForce RTX 5060 Ti 16GB GDDR7`, consistent with catalog identity `asus-dual-rtx5060ti-16g`. The search index showed one image and a new item; the image's creator, exact variant association, current status and reuse grant were not independently established. Treat it as a **lead only**, not an eligible live view or permanent photo. The indexed page is not a fresh provider API response.
- [eBay item 127828174351](https://www.ebay.com/itm/127828174351) was indexed as `DUAL-RTX5060Ti-16G-PF` and out of stock. Its suffix differs from `DUAL-RTX5060TI-16G`; the shared family name does not establish an exact match. Treat it as an ambiguous lead only and recheck current listing status.
- Amazon public search returned no verifiable ASIN or variation in this pass. Do not fabricate one or infer rights from a search result. Jina's anonymous listing retrieval returned an authentication/IP-reputation block; no bypass was attempted.

All observations are dated discovery notes, not current availability claims. No listing image was copied, and no image from these observations changes coverage.
