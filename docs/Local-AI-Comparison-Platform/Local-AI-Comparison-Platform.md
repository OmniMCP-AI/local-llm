# 本地 AI 配置比较平台：可行性、数据策略与内容共创方案

> 调研日期：2026-11-20，中国标准时间（UTC+8）。面向 Tony：以营销和产品判断为主，不假装已经拥有硬件实验室。下文“已核实”指本次打开的官方页面、文档或当事人帖子；服务商自己的测试仍是其自述，不是本项目独立复测。“建议／目标／预算”均为规划假设，不是已发生的数据。本次没有运行模型、观看或下载评测视频、购买硬件、创建网站或社区，也没有设置任何定时采集。

> **同日范围补充导航**：云／本地价格、context与prefill/TTFT见第十五节；Wiki知识库＋自托管模型顾问见第十六节；10人电商团队容量与回本见第十七节；时间序列指数、自测报告与预测市场风险见第十八节。核心入口升级为“任务/约束→有证据的选择”，不扩张首轮建设承诺。

> **新增设计导航（补全）**：第十九节为Footprint Network风格动态探索、声明式版本化视图与亮/暗/二次元换肤；第二十节为新闻辅助价格预测、无泄漏回测及“现在买还是等”（不同于预测市场）；第二十一节为X/社区/网站/TikTok/YouTube Shorts传播与分期范围映射。全部是设计提案，不是已上线能力。

> **开放研究层导航**：第二十二节把网站知识库/数据库规划为兼容外部agent harness的只读MCP证据接口；第二十三节探索AI投资研究视角。愿景扩大为个人、团队、研究与投资观察四层，建设仍分期；Typeface含义未确认，不据此选型。

> **开放仓库导航**：第二十四节规划公开GitHub知识/数据仓库，与网站、MCP和下载版本共享证据ID、schema和release；先审许可与隐私，不把现有私有研究库公开。

## 一、先说结论：可以验证窄切口，不值得先建“全组合巨库”

**值得做一个内容驱动、少量可信数据支撑的决策原型；不建议先做通用本地 AI 榜单，更不能把“扒遍全网”当成护城河。**

最重要的新发现是 [local.ai](https://local.ai/about) 已经明确在做整套配置比较：模型、agent harness、硬件、推理引擎、量化与运行配置，连接 intelligence、任务时间、硬件成本。它的 About 还说明按具体量化版本评估、保留缺失值、允许调整图表权重，底层数据来自 Exo Labs。这个方向不是空白市场。[1] 此外 LocalScore、llmfit、llm-speed、Local LLM Advisor 也覆盖相邻甚至直接重叠的需求。

Tony 可尝试的差异化假设是：

1. **给非硬件专家一个能解释的答案**：先问用途、已有机器、预算、地区、是否接受二手、是否能折腾，再推荐配置；专家可展开证据和筛选，不要求新手先学量化。
2. **围绕营销实际任务建立双通道**：本地中文文案／资料整理，以及可复现的 ComfyUI 商品图／素材工作流。两者共用硬件与成本资料，但不混成一个性能总分。
3. **地区真实购买成本＋失败与维护成本**：中国与海外市场分开，记录价格口径、OOM、安装障碍、持续运行表现，而不是宣称某卡“耐用五年”。
4. **YouTube 解释、社区复现、网站留证**：每次内容产出回流一个带版本和来源的配置案例，不是再做一批没有证据的“最佳 GPU”文章。

最大的三道门槛不是网页开发：**可重复的测量、数据使用权、目标用户是否愿意为决策付钱。** 特别是 Artificial Analysis（AA）数据条款含比较／选型产品的反竞争限制；免费 API 并不等于可以把 Intelligence Index 搬进商业比较站。[14] Tom’s Hardware/Future 也禁止未经许可的自动抓取；淘宝客数据不能默认沉淀成可公开再分发的长期价格库。[21][24]

**建议顺序：10–12 次真实选型访谈 → 人工配置建议卡＋一张小表 → 经授权的少量测试 → 再决定是否产品化。** 不先买卡，不先租一堆 GPU，不先申请十个平台账号。若没有区别于 local.ai 等替代品的明确价值，就把它保留为内容系列，不扩张成数据库创业。

## 二、用户是谁：卖“少走弯路的选择”，不是卖行数

### 2.1 首批人群与任务

| 人群 | 他真正想回答的问题 | 优先输出 | 暂不承诺 |
|---|---|---|---|
| 有电脑的营销人／独立创作者 | 我的机器能不能离线整理客户资料、写中文草稿、批量做图？ | 现有机器方案、安装难度、等待时间、隐私边界 | 小模型等于云端顶级模型；离线天然零泄漏 |
| 准备升级的个人／小工作室 | 多花钱换显存还是速度，值不值？ | 同任务升级对比、全机成本、是否可不升级 | 按显存容量一键判断所有任务 |
| 熟悉部署的技术用户 | 同一模型哪种量化、backend、OS 更合适？ | 严格筛选、并排表、原始参数与日志 | 所有平台的无条件冠军 |
| Edge AI 开发者（后续） | 手机上／小主机上能否持续离线执行指定任务？ | 设备与runtime兼容、持续延迟、能耗、回退情况 | 用桌面 GPU 数字预测手机 NPU |

先服务**本地推理**。微调／LoRA、全量训练另立任务分类，不能拿推理所需显存回答训练容量；并发服务和个人单用户也分开。文本、图像、视频使用不同的工作负载与单位。Agent 工具链的网页访问／外部 API 还会改变“本地／离线”属性。

### 2.2 从“一句答案”到专家筛选的多入口（均为拟议功能）

- **我只想知道选什么**：选“已有机器／准备购买”，填预算、地区与币种、任务、可接受等待、系统、是否必须离线、是否接受二手、安装容忍度。先给一个推荐及一个替代方案；证据不足时应回答“目前无法可靠推荐”。
- **我已经知道候选卡**：勾选任意 2 张以上目录内 GPU，像用户提到的 Tom’s Hardware 对比体验那样做横向表。这里是交互类比，不是声称 Tom’s Hardware 已提供本文全部本地 AI 功能。
- **我是专家**：按具体模型revision、GGUF文件、量化、context、OS、驱动、runtime、offload、并发、数据级别过滤，再看图表；没测过的单元格显示“未知／不兼容／未测”，而不是禁止选中或伪造补全。
- **按预算／人群进入**：“已有12GB显卡”“只想用中文小模型”“Windows少折腾”“素材工作室”等是用户入口标签，不是预设哪张卡一定获胜。预算档位允许自行填写，不在没有地区报价时写固定推荐。

每张 GPU 页应有规格、适用／不适用任务、在本协议下的优点与限制、显存边界、安装与供电注意、价格来源与时间、实测覆盖、稳定性观察、未核实信息。 pros/cons 必须区分厂商规格、测试结果与编辑判断。

并排表按行分组：**规格 → 能运行的具体artifact → 相同工作负载表现 → 质量与约束 → 价格/TCO → 稳定性与支持 → 证据**。两张卡无法形成严格匹配时，展示差异警告，不生成百分比胜负。未来可保存带过滤条件和数据快照版本的对比链接；首版不需要账户或跨设备收藏。

### 3.1 需求信号：有问题存在，但还没有付费验证

本次读到四个具体信号，都是定性材料，不能推算市场规模：

1. [LocalLLaMA：3090 还是 5070 Ti](https://www.reddit.com/r/LocalLLaMA/comments/1s916kt/which_gpu_for_local_llm_inference_3090_or_5070_ti/)：提问者把Tensor算力、代际、显存与实际推理支持混在一起，明确说找不到想要的实际比较。产品应解释“规格峰值≠我的任务速度”。
2. [LocalLLaMA：什么价格才值得买](https://www.reddit.com/r/LocalLLaMA/comments/1six0yx/which_gpus_are_worth_it_at_what_price/)：用户担心欧洲二手旧卡价格与风险，不愿无限折腾。说明地区、成色、安装成本不能省略；帖子报价不是今日市场报价。
3. [Puget官方更正及用户反馈](https://www.pugetsystems.com/labs/articles/intel-arc-pro-b70-multi-gpu-ai-inference-performance/)：官方承认用户发现token计数问题，也承认实验室选的模型不一定是大家真正想跑的模型。这里是实验室转述的反馈，不是本项目采访；支持“社区选题＋受控复测”。
4. [Arena数据集许可讨论](https://huggingface.co/datasets/lmarena-ai/leaderboard-dataset/discussions/2)：另一位开发者明确正在做模型/GPU部署规划，希望使用开源质量分数；官方回应数据集为CC BY 4.0。说明“质量＋配置建议”确有开发需求，也说明已有其他人在做，且许可是实际问题，不是付费用户证据。

ComfyUI 两个搜索命中的跨GPU讨论页本次正文抓取超时；一次公开网页备用读取只返回挑战页，未继续挑战或登录。**不把搜索片段的性能数值、评论或热度当已核实证据**。因此仍需要直接访谈营销创作者，不能用硬件爱好者发帖替代这一环。

## 四、能力分数的“一站式聚合”：可以同屏，不能胡乱合分

### 4.1 四种数值必须分栏

1. **模型能力**：例如 AA Intelligence Index、某具体HF榜单的IFEval／MMLU-Pro，测的是特定协议下能力。
2. **人类偏好**：Arena文本榜用Bradley–Terry方法（类似但不等于直接使用Elo），有类别、置信区间、票数和日期；Agent Arena又有不同方法，不能混用。[15][16]
3. **本地执行表现**：具体artifact、机器和runtime上的prefill、decode、TTFT、任务耗时与失败率。
4. **普及度**：HF downloads、likes、trending只作发现与筛选。官方说明下载统计按特定文件请求计数，甚至HEAD也可计入，GGUF亦有特殊计数；它不是人数、更不是智能或质量。[7]

AA本次方法页为 **Intelligence Index v5.0.1**，列9项评估、知识工作／编程／科学／通用四类权重各25%，主要为英文文本；不是人类IQ，也不直接代表中文营销能力。[13] local.ai 的同名 Intelligence Index 是另一套由 τ²-bench、GAIA、GDPval 组成的自定义加权指标，**不能与AA指数混为一谈**。[1]

不要计算“0.4×Arena分＋0.3×Intelligence Index＋0.3×tok/s”。量纲不同、任务不同、采样不同，归一化后也不会自动科学。可提供用户偏好排序，但必须清楚标为产品规则，不冒充统一能力测量。

### 4.2 聚合表的最小字段与本地匹配

每条能力观测至少存：benchmark名称／版本、任务子集、原始分数及单位、样本量／重复数（缺则标缺）、CI是否提供、评测日期、模型ID与revision、precision／quant、prompt/chat template、工具／harness、thinking budget、原始来源、许可和匹配级别。

匹配级别建议为：**同一artifact实测 → 同revision但不同量化的参考 → 仅同模型家族参考 → 不可匹配**。托管模型的路由、系统提示、推理预算可能未知；某模型BF16分数不能被标成其Q4 GGUF已验证分数。可显示“上游能力参考，未验证本地量化损失”，用户指定质量硬门槛时不能靠这个通过。

HF“排行榜”入口必须选定具体榜单、任务、日期，不设置含糊的“HF排名”。本次Open LLM Leaderboard文档列IFEval、BBH、MATH Lvl5、GPQA、MuSR、MMLU-Pro六项，结果集有Model sha、Precision、Flagged等字段；本次打开的结果集README未见显式数据许可，故不能因Hub上能下载就认定商业再发布自由，也不能称其为2026最新完整能力榜。[8]

### 4.3 关键商业门槛：AA不能“免费API搬过来”

官方API文档要求署名，Free目前标100次／24小时窗口、Pro 500次；额度不是使用许可。[14] 本次读取的 **Data Platform Terms v1.1，2026-08-19修订**：

- §2.3允许内部使用、一定的图表分享／简短引用，需署名；
- §2.4限制原始数据再分发、面向客户的原始数据嵌入、与第三方数据合成对外产品等；
- **§2.5：用于面向第三方的benchmark、排名、比较或模型／provider选型产品，需要事先书面同意**。

本项目恰好可能落在该范围。结论是：**MVP只做方法说明与来源跳转，不以AA数值建立功能性数据库；若要完整聚合，先获得覆盖比较网站、缓存、历史、图表与导出的书面授权。** 买Pro不自动解决。这里是产品风险判断，不替代律师意见。

Arena官方公开leaderboard数据集当前README标CC BY 4.0，并有官方工作人员确认；可在核对具体版本和上游约束后按署名要求使用该数据集。不要抓对话、私有票务或复制整站，网站条款与指定数据集许可要分开。[15][16]

## 五、二维四象限与“斩杀线”：比较配置，不给GPU贴永恒标签

以下是拟议图表逻辑，不是本次做出的图，也没有虚构坐标。

### 5.1 先锁定可比较集合，再画图

设集合 S 只含：同一workload版本、同一模型artifact／允许的质量门槛、同context与输入输出口径、同并发与缓存模式、可比runtime设置、同地区／新旧条件／价格日期／税运口径的有效配置。若比较整套“不同模型”方案，先按**同任务质量达标**过滤，再用完成任务时间比较；不得把不同tokenizer的tok/s直接当同一种产出。

- 横轴：可切换**购置成本**、指定周期**全机TCO**、或**每个质量达标任务成本**，不能把三种成本混放。
- 纵轴：可切换同任务吞吐（越高越好）、或耗时（越低越好，需明显改变方向）。文本与图像分别画；同一张卡可有多个不同配置点。
- 用户拖动预算线 B、最低性能线 P，形成“预算内且够快／预算内但慢／超预算但快／超预算且慢”。这只是用户阈值，不是统计优劣定律。
- 圆点表达实测、空心表达经审核社区、虚线表达估算；点开出现test ID、测量日期、样本量、价格样本、质量证据和全部条件。缺失不是零，无法形成坐标的点列在“资料不足”。

### 5.2 Pareto frontier（用户说的“斩杀线”）

在上述匹配集合内，配置 a 支配 b，当且仅当 **成本 C(a)≤C(b)，性能 P(a)≥P(b)，至少一项严格更好**。未被其他点支配的集合形成前沿。不必把点连成暗示连续可购买的曲线。

先通过质量、兼容、显存、稳定性、离线要求等硬约束，再算前沿。前沿点不一定适合每个人；更便宜但噪音大、需要Linux或二手风险高的配置可能被用户排除。不能把LLM前沿拿去推荐ComfyUI，不能把电费前沿叫作购机性价比。

小幅差距在误差范围内时，展示“前沿候选带”：只有 a 的保守性能下界仍不低于 b 的乐观上界，且 a 的成本上界不高于 b 的成本下界，才标强证据支配；**价格区间不是性能置信区间**，没有统计CI时只显示观察范围和证据不足。不要因为漏测某个更好配置，就称当前前沿为全市场最优。

云端只作另一个可切换场景：加入租机／API费、网络与冷启动、存储、隐私限制、闲置利用率；质量不等的云模型不能仅凭每token价与本地模型直接算回本。

- 不计划“抓字幕→LLM提取→全部转售”这条捷径；API允许读到也不自动等于可进行所有二次加工。
- 创作者愿意在YouTube之外**直接提供其自有测量表和明确授权**，才把那份独立来源的数据列入待审库；需另核对内容、商标和第三方素材权利。

### 7.2 价格数据口径（拟议规范）

单条 observation 至少记录：来源、原始listing和seller ID、抓取／提供时间、GPU芯片和VRAM、板卡厂商/完整SKU/GTIN、显存改装状态、独立显卡或整机/外置盒/捆绑、condition、新/二手/翻新/仅零件、卖家类别、库存、地区与目的地、币种、税、运费、进口费、是否可退／保修、优惠及其资格、失效时间、是否API或合作方数据、可存到何时、原链接。

- `到手成本 = 商品价 + 必付税 + 运费 + 已知进口费 − 用户实际有资格的优惠`。税或运费不明就是“不完整报价”，不凭空记0。
- 一口价、拍卖当前出价、best-offer标价、成交价分别存；没有成交事实不称“真实成交均价”。
- 排除散热器、配件、订金、空盒、缺货、损坏卡、整机拆价假设、明显错配；水冷与风冷／改显存卡分组，不能只按“4090”标题去重。
- JD／淘宝商品页最低变体价可能不是GPU本体；88VIP、新客券、地区补贴、PLUS、支付优惠、凑单分别标条件，不把所有人都拿不到的价设为默认。
- 原币保留；跨币比较使用注明来源与时点的汇率参考，不把换算价格当本地含税可买价格。中国／美国分独立曲线。

### 7.3 区间、均价与趋势的抗误导设计

默认显示**中位数＋P25/P75＋有效样本数n＋独立卖家数＋最近成功观测时间**，同时提供核验后的最低／最高报价范围。不是用搜索第一页的算术平均叫“市场平均价”。

建议每卖家每匹配SKU每天只取一个合格offer进入摘要，重复刊登合并，跨源同一个offer合并；保留去重前后计数。异常值进审核隔离，不因为高价或低价不合预期就悄悄删除。显示平台覆盖和搜索截断，承认联盟可推广商品的选择偏差。

用户要求的“均价”可另给：n≥10且至少5个独立卖家时计算10%双侧截尾均值，并写明规则；不足则显示“样本不足”，只给单个报价或观察区间，不计算貌似精确的总体统计。该门槛是产品建议，不是统计保证。

趋势图只从**获准记录的第一天**开始；没有合法历史就不画过去一年。每天一次只是采样，不代表日内最低或完整的每日涨跌。缺测留空、失效offer不延伸为今天仍可买、促销期间注释条件变化；同比／环比仅在覆盖与分组足够稳定时给出。价格来源条款若不允许长期保留，不能靠匿名化／算中位数擅自绕过，历史功能应关闭或改用合同允许的统计。

**价格MVP提案**：先看三张卡（与实测候选相同：RTX3060 12GB、RTX3090 24GB、RTX4090 24GB），每地每卡最多5个预审商品／卖家，固定一个目的地；仅在拿到合适权限的**一个地区、一个源**试行每日一次观测。Tom’s只作编辑参考；JD/淘宝及eBay成交历史未解决权利前不列为已上线覆盖。最低只显示报价卡，样本达不到门槛不强求均价。多地区、四源齐全属于后续而不是六周MVP承诺。

## 八、测量协议：数据库最重要的表不是GPU表，而是一次测试

以下为拟议协议，不是已经完成的benchmark。

### 8.1 基本环境

硬件ID至少包括GPU实际设备ID、厂商/板卡SKU、物理/可用VRAM、多卡数量与连接/PCIe代际和实际通道、CPU、内存容量/速度/通道、主板、存储、PSU额定与型号、散热/环境温度、是否笔记本/共享云机。Apple unified memory、NPU共享内存和独显VRAM不能无说明等同。

软件记录OS发行版/版本、kernel、驱动、CUDA/ROCm/Metal等backend、runtime精确build或commit、framework、编译标志、kernel/attention实现、启动参数、CPU/GPU offload、功率上限、并发与其他进程。LM Studio是产品壳的一部分，具体runtime也要固定。[9]

### 8.2 文本LLM

- 模型仓库＋不可变revision、文件SHA、tokenizer、chat template、架构、总参数／MoE激活参数、量化方法/位宽/格式、实际文件bytes、license快照。
- 参数量≠磁盘量≠运行内存。权重只是内存的一部分，KV cache随context、batch、层数和精度改变，还需要runtime工作区；小模型也不保证每个NPU都支持。
- 输入、输出长度按**该tokenizer的实际token数**固定；context上限与已有context深度分别记录。控制KV精度、缓存命中、speculative decoding、batch/concurrency、EOS策略。
- 分开报prompt processing/prefill tok/s、decode tok/s、TTFT、首个可见答案等待、端到端任务时间；推理token和最终答案token也分开。吞吐高不代表单用户等待短。
- 冷启动（下载不计／另计、加载、首次编译）与热运行分开；原始重复样本、p50、失败/OOM/timeout、峰值显存/RAM保留。建议文本20个热样本作为初步分布；p95仅作小样本提示，重要尾延迟另做至少100请求的固定验证，不用5次运行包装出可靠p95。
- 质量和速度分别测试：技术固定token长度测试不等于实际文案质量。另用原创／获权的中文营销任务集盲评事实保真、指令遵循、品牌约束、泄露风险、可编辑性；评分标准、评审数、分歧公开，不能冒充通用能力榜。

llama-bench已有重复数、prompt/gen/depth、KV类型、offload与JSON/CSV等输出，适合当测量基础；TTFT和真实任务需要另有明确测量边界，不把微基准输出硬称完整应用体验。[25] Puget公开的tokenizer更正尤其说明跨模型tok/s不能靠默认词表乱数。[12]

### 8.3 ComfyUI 双通道

每个workflow保存经许可的API-format JSON、hash、ComfyUI commit、所有自定义节点版本和依赖、checkpoint/VAE/CLIP等文件hash、precision、seed序列、prompt、分辨率、batch、steps、sampler、scheduler、guidance、attention、offload、模型缓存规则。

固定可复现的seed**序列**，每张卡用相同序列；不能每次不变seed让缓存跳过计算。Comfy Desktop官方性能测试会递增seed避免重复缓存，并记录成功／失败、系统信息；其时间是服务端执行而非用户从点击到拿到文件的等待。[17] 因而本站同时区分加载／排队／执行／保存与用户端总等待。

图像报秒/张、每批时间与峰值内存；视频另记帧数、分辨率、帧率、片长与秒/片，不能把it/s直接和别人的不同工作流对比。初版至少1次warm-up＋5次热运行，公布全部值与中位数，不给稳健性不足的尾延迟。质量保留获权的输出样本/盲评，不以减steps、降分辨率和量化后“更快”冒充无损提升。OOM、需要lowvram/offload的配置另成行。

### 8.4 稳定性、可靠性、耐用性要拆开

- **本次可测**：固定时段/重复任务的崩溃、驱动重置、OOM、降频、温度、噪声（有校准设备才报数值）、完成率。可提议每台2小时持续测试，但“2小时没挂”只能这么写，不能推为长期故障率。
- **可查事实**：厂家保修、支持周期承诺、ECC/管理能力、消费／服务器驱动和供应商服务，按地区与型号核对。
- **暂不能知**：二手卡真实历史、未来寿命、MTBF、几年后损坏概率。游戏benchmark、TDP、保修年数都不能推算“耐用分”。

能耗以墙上功率计积分为全机口径；GPU传感器只能称GPU能耗，注明采样频率、基线、仪器与误差。`任务能耗Wh = ∫功率W·时间h`，不能用额定TDP当实测电量。没有测量就不画能效排名。

## 九、小模型与Edge AI：纳入分类，别一次扩成全设备榜

分类从“LLM大小”扩成：模型族/任务/模态、总与激活参数、revision、量化artifact、文件bytes、运行内存和KV需求、context、设备类型、加速器、OS、runtime、兼容状态、能力观测、性能观测。

首版提供一个**小模型参考通道**：Qwen2.5-1.5B-Instruct的官方模型卡和已获权的LocalScore 1B类别链接等，不声称已覆盖手机／NPU。Qwen官方卡给出1.54B参数，能说明UI四舍五入的“2B”与精确参数不同；这类字段要存精确值和展示标签。[26]

Edge路线建议：

1. 桌面CPU/iGPU的小模型：先用已有机器，锁一个设备、一个runtime、一个artifact；
2. Apple Silicon统一内存及一台Jetson或其他边缘板，作为**两个分开的设备案例**；
3. 再看一款Android和一款iPhone的明确任务，不先覆盖所有手机与NPU。

ONNX Runtime官方列多种Execution Providers，算子分配可发生CPU回退；ExecuTorch明确不同backend有硬件/算子限制，通常需要各自导出的`.pte`，Core ML、Qualcomm等有不同路径。[27] 因此“支持ONNX/Core ML/ExecuTorch/llama.cpp”只能标到**模型＋导出格式＋精确runtime＋硬件＋系统**组合，不能把框架存在写成此模型已在所有NPU加速。

Edge追加字段：持续负载前后p50/p95、降频时间、峰值与稳态功率、J/任务、电池Wh/任务与续航测试条件、内存压力/系统杀进程、充电/电池模式、设备温度、CPU fallback占比、网络断开验证、遥测/模型下载/工具调用是否离机。静态TOPS不能跨设备换算实际LLM速度；隐私也要验证，而非贴“本地”标签即保证。

## 十、推荐技术架构：普通栈足够，先把证据链建对

**这里只做方案，不实现或部署。** 建议网页UI（如Next.js或同类成熟框架）＋Postgres版本化关系核心＋受许可约束的对象存储＋任务队列；不需要一开始上向量库、微服务集群或巨型图数据库。

数据流：**获准来源 → 隔离原始区 → schema/权利/单位校验 → 归一化版本层 → 审核 → 只读API/cache → 推荐、对比与图表**。原始区同样受存储／到期／删除条款约束，不是“先全部留着以后再说”。

### 10.1 最小实体

- `hardware_sku` 与 `machine_configuration`：芯片／板卡不等于整机；多卡拓扑另表。
- `model_family`、`model_revision`、`artifact`：参数、文件、格式、量化、tokenizer、许可分离。
- `runtime_release`、`environment_snapshot`、`compatibility_observation`：OS/驱动/backend及支持、失败、未验证状态。
- `workload_version`、`workflow_revision`、`test_run`、`metric_sample`、`quality_evaluation`：原始样本、单位、统计方式、协议。
- `benchmark_definition`、`capability_observation`：AA/Arena/HF的版本、来源与不可直接匹配标记。
- `seller_offer`、`price_observation`、`price_cohort_summary`：挂牌与成交分开、地区与优惠资格、到期策略。
- `source`、`rights_policy`、`consent_record`、`provenance_edge`、`review`、`correction`：每条派生结论可回溯来源及权利。

每个数据点都有observed_at、published_at、ingested_at、valid_until、协议版本、授权范围、再用/导出标记。变更保留新版本，不静默覆盖历史结论；受限来源到期须删原始和可反推衍生缓存，对象存储/备份也纳入执行策略。

### 10.2 可信度、反作弊与安全

标签建议：**A受控复测、B结构完整社区实测、C外部来源自述、D模型估算、U未知**。这是来源类别，不是伪造的概率；另列方法完整度、硬件验证、重复次数和时间。签名证明提交来源而非机器真实身份。

社区异常：查重复日志、参数冲突、离谱吞吐、GPU与VRAM不匹配、跨版本混用；异常隔离、复跑后升级。Verified Lab徽章靠审查，不出售。赞助不改等级或排名。

以后若提供可复现runner，只接受白名单版本和明确用户授权；**不在网站服务器执行用户上传的任意ComfyUI节点、Python插件、pickle权重或shell脚本**。容器不是万能隔离，尤其有GPU、网络、挂载和凭据时。采用签名runner、固定依赖、低权限、无秘密环境、网络与文件范围隔离、资源限额；首版完全人工在受控设备跑预审workflow。

投稿默认移除主机名、用户名、序列号、IP、路径、客户prompt、访问token；原日志扫描并让投稿者预览。遥测需主动同意；未经同意不从Discord、电脑或runtime读取信息。删除/撤回机制要与已发布开放许可的不可撤回性分别解释，不能承诺删掉互联网上所有副本。

### 10.3 刷新频率是提案，不是已经运行的系统

价格：权限允许的SKU每日一次；模型元数据：每周及重要版本发布；runtime/OS兼容：版本事件触发人工审核；基准：协议/关键引擎变化时小样复测；来源许可：接入前、条款变更和定期复核；稳定性：独立持续测试批次。过期就标旧，不自动把旧build结果改成新build。

## 十二、4–6周验证计划与经济账（全部为假设）

| 阶段 | 提议工作 | 继续条件 |
|---|---|---|
| 第1周 | 访谈10–12位目标用户，至少一半营销创作者；让他们展示最近一次真实选型和现用替代品；对照local.ai/llmfit，不引导“你觉得网站好吗” | 找到至少5个有明确任务、预算、期限且现有工具没解释清的案例；否则转内容项目 |
| 第2周 | 人工制作5份有来源的选型建议卡；核查一个价格源及一个可用基准源的权利；预审2个workflow | 来源无权即移除，不以开发之后再补授权为策略 |
| 第3–4周 | 在有设备访问的前提下跑4格方法样本，再决定是否扩至45格；完成受试者可阅读的对比表／轻原型设计 | 若重复差异超出预设容差，先查环境；不要一边不稳定一边扩库 |
| 第5–6周 | 让8位目标用户完成“已有机器／买卡／做图”任务，与其原办法对照；试3个视频选题和社区投稿表的可理解性 | 根据结果决定网站、内容或停止；不以播放量代替决策效果 |

建议预先写下而非事后调低的验证目标：8人中至少6人能在10分钟内解释选哪套及原因，至少5人表示这次减少了具体的不确定性；至少3人愿意留下一个真实待决策项目并约下一次验证，而非只点赞。愿付费可通过明确价格方案访谈验证，但**口头愿付费不是成交**。测量试点目标：同环境热运行中位数跨两次session偏差≤10%作为排查线（不同任务可调整但预先声明），关键字段完整率≥95%，可公开数据100%有已检查权利基础。样本很小，均是go/no-go管理目标，不是统计证明。

停止／缩小条件：六周后用户用现有站点同样容易解决问题；只能靠未经许可抓取才有内容；拿不到可复测设备；测试与剪辑工时超过可维持节奏；用户只想免费查榜且没有后续价值。不要把注册数、Discord人数和数据库行数当唯一KPI。

### 12.1 成本模型

- 月成本 `C = 人工小时×内部时薪 + GPU租用小时×实际报价 + 自有设备折旧/借测成本 + 电费 + 存储/带宽/DB + 数据许可 + 内容剪辑 + 社区审核`。
- 测试时间 `H = Σ(加载＋warm-up＋重复次数×单次耗时＋故障处理)/3600 + 环境搭建/复测`。无法从45格直接得到租机账单，先用4格估工时。
- 全机TCO `= 购置/升级 + 指定周期电费 + 维护/支持 + 软件许可 − 明确假设的残值`；沉没设备成本和新增升级成本分视角显示，利用率由用户调整。
- 本地与云的盈亏平衡只对**质量等价、隐私可接受的相同任务**算：额外前期成本 ÷（云单任务成本 − 本地可变任务成本），分母≤0或未知则不存在可报告的回本点。

规划工时可先按负责人20–30小时/周、技术测量协作者15–25小时/周估，4–6周即总计约140–330小时，另加不确定授权等待。这个范围是工作量预算，不是市场雇佣报价。现金预算没有经核实的实时报价，不在此捏造GPU租价、许可费或云账单。

敏感性：工时/返工翻倍通常比数据库存储翻倍更致命；视频workflow单次耗时、驱动故障、缺硬件最可能拖期。租云卡适合初试协议，但不能据此声称测到了家用机墙上电量、噪音、长期可靠性或二手质量。

### 12.2 收入假设及冲突

免费决策卡／基础比较用于获客；可能测试的收入包括付费选型咨询、工作室部署前评估、可复现workflow培训、团队报告及许可明确后的专业工具。联盟链接和硬件/云厂商赞助是辅助，不应当成已验证主收入；硬件购买低频，面向消费者的订阅未必成立。

每页披露affiliate、借测、赞助与返佣；未返佣的选项同样展示；不按佣金排榜，不售“最佳GPU”徽章。若付费咨询和数据库选择规则存在冲突，公开规则与可替代选项。长期资产是**可信的任务案例、标准化测量和目标人群信任**，不是收集了最多未经许可的数据。

## 十三、YouTube＋Discord：内容围绕数据产品，不另造三个创业项目

### 13.1 内容定位

中文主叙事：“我用真实营销任务，验证一台机器到底能做什么；成功与失败都给你看。” Tony负责提问、任务定义和商业解释，技术协作者负责可复核测量；不假装是半导体专家，不复述规格就叫评测。

每期格式：**观众问题 → 明确任务和约束 → 候选及测试ID → 安装／执行 → 失败与修正 → 质量盲评 → 时间/成本权衡 → 谁该买／谁不该买 → 指向网站证据页**。脚本先写假设，拍完再下结论；没有数据不写“某卡吊打某卡”。视频不会随着驱动更新自动正确，网站标版本和后续更正，描述区将来可放固定快照链接。

前三期提案（不代表已录制或已知结果）：

1. **《先别买显卡：现有机器能不能完成12个中文营销任务？》** 用一个固定小／中模型，展示“能加载”“等得起”“输出能用”的区别；顺便教观众读参数量、磁盘与运行内存。
2. **《便宜二手大显存，还是更快的新卡？一张严格同条件的比较表怎么读》** 从已能取得的两台设备和三张卡候选中选，不预定胜者；展示地区报价样本、整机供电、未知寿命和升级成本。若没有对照设备，改做方法解读，不假装实测。
3. **《同一套ComfyUI工作流，为何别人的秒数与你不同？》** 固定SDXL或FLUX.1-schnell，解释冷/热、seed缓存、分辨率、precision、offload和质量，带观众复现一个test ID；不先做视频大模型大战。

获客路径：长视频解释 → 短片提一个真实误区 → 搜索落地页解决具体“我这台机子”问题 → 投稿／纠错 → 下一期。SEO围绕有证据的任务和配置，不批量生成十万个空的“模型×GPU”页面。

### 13.2 Discord最小共创结构（未来才开）

初始五个频道足够：

- `start-here-and-method`：范围、隐私、授权、证据等级、赞助政策；
- `my-rig-and-questions`：用途/预算/地区/现有配置模板；
- `bench-and-workflow-submissions`：以forum标签分LLM/ComfyUI/Edge；结构化提交和日志预览；
- `next-tests-and-votes`：候选与投票，明确截止和资源约束；
- `results-and-corrections`：网站规范test ID、复现差异、撤回/更正状态。

角色：观众、贡献者、复现者、数据审阅者、维护者/主持人；赞助商独立披露角色，没有审核或排名特权。投稿者不能单人给自己的结果Verified，存在利益关系应回避。

流程：投稿任务 → 检查权利、可运行与安全 → 形成3–5个可承担候选 → 48–72小时一人一票（期限是提案）→ 维护者按“用户价值、覆盖缺口、可复现性、成本”说明最终排程 → 测试 → 双人审核关键结果 → 网站发布版本 → 内容解释。**投票决定先测什么，不决定哪张卡更快、更好或数据真伪**；怀疑刷票可暂停复核，不以粉丝多少改变测量。

不要求投稿客户资料、账单、精确地址、设备序列号或私有prompt。公开授权和反馈选项分开；不抓频道聊天建立隐藏用户画像。先人工维护，不急着做积分、自动角色和投票bot，更不把社区当免费测试劳动力。

## 十四、目前未知、下一步最便宜的验证与最终判断

| 问题 | 本次判断／置信度 | 低成本下一步（均待决定后执行） |
|---|---|---|

**最终建议：做“选择与解释”的窄原型，不做“全知巨库”。** 首个值得执行的动作不是写爬虫，而是拿一个真实营销用户的现有电脑、任务与预算，做一份来源清楚、可被质疑的建议卡，并让他与现有竞品的答案比较。如果连五份人工建议都无法产生明显价值，自动化只会让没有差异化的内容更多。如果能解决具体选择，再把这些判断沉淀成有版本的配置表、复现实验和内容系列。

### 15.2 Session成本计算与云／本地并排UX

场景表单新增：语言/原始任务、输入内容大小与**各模型实际token数**、预期输出和thinking预算、最大context、多轮历史、调用次数、并发/峰值、prefix重复比例、可接受Batch等待、连接复用、客户端地区、隐私约束。相同文章在不同tokenizer下数量不同，不能拿一个模型的token数给所有模型估价。

对请求 j，把输入分为互斥的未缓存普通token `Iu`、缓存读 `Ir`、各TTL缓存写 `Iw,k`，实际输出计费token `O`（按provider定义处理reasoning）；用适用的上下文/时间/处理档/地区费率 p：

`Cloud_session = Σj[(Iu×pu + Ir×pr + Σk Iw,k×pw,k + O×po)/1,000,000 + 工具调用费 + 其他本次使用费] + 会话分摊存储/传输/最低承诺`。

若provider只报告包含缓存的input总数，按文档拆分，**不能先对总input收费再额外对cached部分收费**；不能同时对同一输入token收普通价和替代式写入价。长context触发全请求加价时必须重算该请求所有适用类别；多轮、失败重试、被收费的思考/工具schema/工具返回内容都计入。缓存命中率用实际cached tokens/输入tokens并显示分母，不用“重复同一个问题”就假设命中100%。

本地展示两个口径：

- 已有机器的**增量现金成本**：新增设备/升级、增加的运行/闲置电量、软件和维护；不把已支出的购机费再次当即刻现金流。
- 新建服务的**全周期TCO**：整机、设置、维护、运行与闲置能耗、必要空间/冷却/网络、预期更换和残值；显示利用率和分摊规则。折旧可作会计成本视图，不再与全额购机现金重复相加。

对比卡先给“满足哪些硬要求、哪些不知道”，再给总session/每合格任务成本区间、延迟分布和质量证据，不给“云一定贵／本地一定便宜”的默认答案。云API不要求用户拥有GPU但依赖网络、账号和服务；本地低利用率、管理员时间或未通过质量门槛时可能更不划算。回本模型及10人团队见第十七节。

### 15.4 上下文、prefill、TTFT：必须精确定义

**Context三层**：①厂商宣称的最大窗口；②当前runtime/账号/参数实际配置的窗口；③该任务上实际测试且输出质量达标的可用窗口。UI分开显示。输入、历史、system/tool定义、检索资料、思考与输出保留如何占用窗口依模型文档，不把“最大输入”和“最大输出”简单相加。标称支持长context也不证明能稳定找回信息、遵循长文约束或避免截断。

**本地prefill吞吐**定义：在特定协议下，服务器实际新计算的输入tokens ÷ 该prefill阶段实测耗时；注明是否分块、是否含prefix cache复用，默认不含磁盘加载、tokenization、网络及首token decode。原始prompt处理总tokens与本次新计算tokens分开。如果runtime无法拆阶段，就标“未知”，不把端到端时间改名prefill。

**客户端TTFT**建议从开始提交请求的单调时钟 `t0` 到收到**第一个有效、非空生成内容增量** `t1`；headers、role、空SSE、心跳和usage事件不算token。若流中可见reasoning先到，另外记 `TT_first_reasoning` 与 `TT_first_visible_answer`，不把后者与另一模型首个thinking chunk当同一单位。服务端通常按chunk发送，若不能确定首token，就严格称“首内容chunk延迟”，保留事件解析规则。

`API客户端TTFT`可能包含连接/TLS、上传、区域RTT、网关/配额排队、服务端排队、prefill和首decode及传输；**prompt_tokens/客户端TTFT不能推导真实服务器prefill tokens/s**。若确有需要，可另设“有效输入率proxy”，写明分母和所有假设，不能与实测本地prefill同列排行。只有provider提供有定义的后端阶段telemetry才能填云prefill栏。

- Streaming报告TTFT、端到端时间、每用户decode/相邻有效输出chunk间隔；客户端chunk间隔不冒充逐token服务端ITL。Non-streaming没有可观察首token，报完整响应等待，TTFT填不可观测。
- 分p50/p95，样本数与失败率并列；统计不同并发、缓存、连接、地区和重试策略，不把失败删掉只报最快值。provider推理已warm与否通常不可知，不声称“强制云冷启动”。
- 冷连接、冷模型、冷JIT、冷KV/prefix是四种不同状态；本地模型已驻留并不意味着KV已缓存。云长连接复用、provider prefix cache与本地KV复用分别标。**没有普遍保证哪边TTFT更低**。
- Prefill常更受计算/批量效率影响、decode常受访存影响，但这是依赖模型形状、context、并发、offload与kernel的倾向，不是全硬件普适定律。Flash Attention、权重量化、KV量化、硬件指令和runtime支持都影响速度、内存和质量；Q4权重不意味着KV也是4bit或所有优化都兼容。上下文增大可能KV OOM或offload，需保留失败点。

### 15.5 配套测试、图表、schema与MVP修订

**拟议长度扫描**：512／4096／16384／32768输入tokens，仅在真实窗口内并为输出/思考/工具保留空间时使用；每个prompt保留原文hash、模型各自tokenizer实际计数与语言/内容类型，固定256输出上限/生成停止规则、并发1、thinking设置与cache策略。技术固定长度试验与实际质量任务分开，不能强迫不支持相同reasoning模式的模型伪装一致。每格拟1次准备＋至少5次热采样作试点，想发布稳定p95则另增至≥100请求并报告不确定性/采样计划。

同artifact能在本地和获准云GPU上部署时优先成对测；商业API不可取得同artifact时，改用同任务质量验收和端到端时间，不叫受控同模型硬件对决。Cache-hit分层必须由usage/日志证实，无法清provider cache的实验标“预期未命中但未验证”，不造nocache保证。

图表增加：TTFT/首可见答案对输入长度，按cache/连接/模型驻留/并发分层；真实prefill独立图；相同tokenizer/模型下decode独立图；质量达标任务的成本/延迟Pareto图。云/本地可以同图表达端到端体验，但不能混入不同口径prefill或不同质量任务。

在第十节schema补：`cloud_model_release`、`provider_endpoint`、`account_eligibility`、`tariff_version`（币种/生效期/促销结束/输入阈值/peak时段/TTL/处理档/税）、`privacy_policy_version`、`token_usage_breakdown`、`latency_event`、`context_test`、`scenario_assumption`。每个值有scope（client/server）、状态（observed/advertised/estimated/unknown）、tokenizer、cache证据和时间戳。

**不扩大45格本地计划承诺**：首版只加五条手动价格参考和计算公式、context三层字段；长context只在一台参考机、一个7B Q4 artifact对16K/32K补2格（若可行），不全矩阵展开。云实测需要明确授权、地区资格与费用上限之后，另选**一个合规可访问endpoint**测相同任务；本次不设置key、不调用、不跑分。现有价格监测、小模型/Edge、HF方法保持原范围。

## 十六、核心产品升级：从榜单到Wiki知识库，再到有证据的配置顾问

**这个功能可以成为主要入口：网站不只是“有很多信息”，而是一套可审阅知识库；聊天把用户的硬件、预算和任务转成有引用的配置方案。** 但“加RAG”本身不是护城河，必须比“ChatGPT＋现有站点＋人工表格”更能解决约束冲突、旧数据和证据匹配。

### 16.1 Wiki与结构化数据各司其职

Wiki由少量经过编辑的说明页起步：显存与context、量化、Windows/Linux差异、冷/热等待、ComfyUI工作流、云/本地隐私、TCO与回本、团队排队。每页关联hardware/model/artifact/runtime/workload实体，标作者、原始来源、许可、更新时间、审阅人、适用版本、变更历史与纠错状态。

跑分、价格、兼容和公式留在结构化层；Wiki负责解释“为何这么选”，不能把一段生成文字当新测量证据。社区改动先是proposal，经过来源/权利/方法审阅才成为published revision；点赞和受欢迎不自动提高可信度。受限文档／私有团队资料需要ACL，授权撤回/到期传播到检索索引与缓存，不能把“做了embedding”当允许保留原内容。

### 16.2 引导式聊天，而不是无边界自主Agent

提问顺序建议：①已有硬件/操作系统；②个人还是团队及任务；③预算币种/地区/新旧偏好；④模型/ComfyUI工作流与质量要求；⑤context、峰值并发、等待容忍；⑥安装维护技能；⑦隐私/离线/驻留硬要求。一次只问缺的高价值信息，可选择“不知道”，用解释或测量建议补缺，不无限审问。

推荐流水线（拟议）：

1. **结构化约束**：LLM把回答整理成可编辑需求卡，用户确认；缺预算或任务时不能擅自替他决定。
2. **检索**：从允许的已审Wiki版本和已授权数据源检索，先过滤ACL/license/有效期，再做关键词＋可选向量检索；检索片段带source ID、适用实体、revision和日期。
3. **受控计算**：通过只读、参数化、白名单查询取对应测试/报价，兼容检查和VRAM估算由版本化规则实现，TCO/回本/Pareto由确定性calculator算；不让模型随口做金额/显存运算，也不允许自由SQL改库。
4. **生成说明**：答案每个重要数值绑定真实test ID/price observation ID/公式版本与时间；未匹配就说未知，引用链接由系统从证据对象生成，不让模型编造。先说明硬约束、建议和替代，再列限制/待验证步骤。
5. **校验与拒答**：数值是否能从证据重算、机器/量化/context是否匹配、报价是否过期、引用是否真实支持结论；检查失败退回结构化表或澄清问题。不在旧报价上承诺今日能买、不把参数估算写实测。

顾问没有购买、开户、下单、发消息、执行社区代码或自动改系统的能力；外部页面中的“忽略规则/上传资料”等只能当文档内容，不成为指令。OWASP明确RAG和微调都不能消除prompt injection，需来源隔离、最小权限与恶意检索测试。[39]

### 16.3 “由Local LLM驱动”要说清部署地点

| 方案 | 用户实际上在用什么 | 隐私/体验边界 |
|---|---|---|
| **网站服务器自托管开放权重模型**（可作为最早LLM试验） | prompt经网络发到网站运营方服务器，由其GPU/CPU推理，不走第三方token API | **不是用户设备本地**；站方可见/处理prompt，需TLS、租户隔离、日志/留存声明、管理员权限及托管商政策。不能宣传“文字不离开你的电脑” |
| 用户自己部署服务并主动连接 | 页面或客户端连接用户控制的推理服务 | 浏览器跨域、安全、认证、远程访问与局域网风险需设计，不能探测或自动连接内网；站方检索请求本身也可能泄露意图 |
| **浏览器端WebGPU推理**（后续可选） | 在兼容浏览器/设备下载获许可artifact并本地执行 | WebLLM官方提供此路线，但受WebGPU、内存、下载量、模型编译/格式与设备温控限制；本地推理不等于网站检索、遥测也离线。[40] |

llama.cpp server官方具备量化模型CPU/GPU推理、并行、多用户、continuous batching、结构化输出与监测等基础能力，说明可试验，不证明指定模型已经能可靠做本项目推荐。[41] 候选模型仍需核实**可商用/再分发/托管用途**、源模型和量化artifact许可；不能因为是GGUF或代码MIT就认定权重自由。模型选型应先跑中文约束遵循和引用评估，不因本站正在用它就给它更高推荐排名。

页面可展示真实“当前顾问模型ID/revision/quant、服务端硬件、配置context、队列长度、客户端TTFT、服务器prefill/decode、近样本统计”，但只有实际测到的指标才显示。服务器GPU统计不可透露其他会话、主机身份或内部地址；没有数据就显示“尚未测量”，绝不用演示数字假装实时。高负载时告知排队／转成静态引导；**不静默切换付费云或上传到第三方**，任何可选云fallback需明确同意及标识。

### 16.4 资源、会话与安全

自托管不是“每次token免费”：有GPU空闲/峰值成本、KV容量、并发抢占、输入长文导致prefill阻塞、运维与审核。聊天服务与本站ComfyUI评测最好资源隔离；参考测试时不能让公众聊天占同一GPU又宣称环境受控。设会话token/上下文/并发上限、公平队列、取消/超时、速率控制；区分等待、推理和冷加载，勿预先承诺性能。

默认最小化prompt日志，建议会话只在完成服务所需的短时内存/有明确TTL的存储中保留；保存方案由用户主动选择，公开分享另确认。反馈授权与聊天使用分开，不默认用客户预算、资料或作品训练顾问；跨会话KV缓存、检索、导出及链接都要有租户隔离与撤销策略。事故/审计所需元数据明确说明，不能一边记完整请求一边标零保留。

### 16.5 分期与评价：先能不用聊天解决，再证明聊天有增益

- **MVP-0**：保留前述表格/方法/人工建议，新增8–12篇短Wiki＋静态向导；没有GPU服务器需求。
- **MVP-1候选**：表格可靠后，先在不公开部署的受控条件评估一个自托管模型；限定推荐范围，只读资料与calculator。若无合适设备访问就停在wizard，不为体验噱头先买卡。
- **MVP-2**：通过评估才考虑小范围聊天体验，展示模型/硬件/延迟和来源；公开服务成本另预算。端侧WebGPU、自带推理服务、广泛agent/skill集成都在后续。

评估集先设计20个代表profile：低显存/小预算、新手Windows、Linux专家、必须离线、大context、未知报价、无权云地区、团队高峰、资料冲突与恶意检索。与静态向导、人类建议、通用聊天＋现有站点做同任务对照。检查数值/引用正确、全部硬约束满足、合理澄清/拒答、过期识别、复算一致、延迟与每方案成本。可以预设“无严重权限/隐私越界、关键金额可100%由calculator复算”等上线门槛；不宣称已经达到。若聊天只是更好看但更慢、更容易错，保留向导＋Wiki即足够。

## 十七、旗舰验证场景：10人电商图团队的配置、云比较与回本周期

“10个人做电商图怎么配”是很好的产品入口，**但10个人不等于10路同时推理，更不等于10张GPU**。把它作为唯一首批团队case，而不是立即扩张成通用企业基础设施配置器。

### 17.1 聊天／向导先拿到什么

- 每天/每月需要多少**验收合格**商品图，多少只是候选、预览、修图或视频；工作日、旺季与增长情景。
- 精确模型、ComfyUI workflow版本/hash、分辨率、steps、sampler、batch、ControlNet/LoRA/放大/去背景等节点；商业许可和产品保真/文字/品牌质量标准。
- 每张验收图平均尝试几次、人工挑选/修图时间、失败重试、合格率；不要用出图次数假装商业产量。
- 高峰到达率/同时提交、可排夜间批量的比例、p95排队/交付时限、是否抢单或预约；10名员工实际工作习惯。
- 文本顾问/营销文案聊天是否与图像任务抢同一GPU；交互LLM和图像长任务的不同SLO。
- 现有硬件/供电/空间/网络/管理能力、停机容忍与备机，隐私/合同/地区限制、预算/现金期限。

没有这些输入时只给待填模板与条件式候选，不说“你们买两台某卡，几个月回本”。

### 17.2 从工作量到容量，不能从tok/s推图像产能

在相同质量/工作流下测量单job服务时间分布、每job输出数、失败与可接受比例、批量效率、加载/切换与资源占用。设有效需求为 `D` 张合格图，验收率`a`，每job产出`b`张，粗略所需job数 `J≈D/(a×b)`；若`a`已包含失败重试，不再重复乘失败系数。迭代依赖、相似候选相关性可能使此公式仅为粗估，应以真实任务日志修正。

粗略稳定容量条件可用 `峰值到达率λ < c×单worker有效服务率μ` 做排查，但并不保证p95等待；到达突发、任务长尾、模型切换、共享GPU内存和批处理都会改变队列。没有实测分布就不报告等待结果或承诺GPU数量。用预审workflow和匿名/合成到达序列做未来容量验证，而不是用LLM tokens/s推图片/小时。

比较至少三种方案：①现有设备＋排程/小升级；②新增本地整机服务；③云端同工作流GPU/托管Comfy，或质量可接受的按图API；可加④本地稳定底座＋合规云处理不敏感峰值。Hybrid需计路由/重复模型存储/切换、授权和数据外发条件，不假定免费无缝。

### 17.3 图像云成本的官方参考，不只看token价格

- **按图片API**：xAI型号表列`grok-imagine-image` $0.02/张、`grok-imagine-image-2.0` $0.04/张。[32] 这是不同服务/模型的标价，**不意味着能复现某ComfyUI ControlNet/LoRA工作流或同等合格率**。没有质量验收不能直接推“每月省多少”。
- **相同工作流租GPU**：Runpod官网RTX4090页列Secure $0.89/GPU小时、Community $0.34/GPU小时，地区库存不同；主价格页本次也显示Secure $0.89，页面自标2026-11-12更新。[42] 这里只引用观察值，实际控制台报价、可用性、存储/开停机和数据政策执行前核实，不使用营销“无闲置成本”取代实际计费规则。
- **托管ComfyUI**：Comfy官网Custom Builds列RTX PRO6000 96GB $3.49/小时、按GPU秒计费、另有模型存储及计划限制。[43] 不把它当整个平台所有运行模式统一价格。另一官方credits文章写0.266 credits/秒和$1=211 credits，与Custom Builds页736.39 credits/小时不是同一个可直接合并的费率；可能服务范围/页面更新不同，**需先确认适用模式，不擅自选便宜者当结算价**。计划月费、月credit过期/充值、Partner Nodes、并行workers、允许自定义模型及超时都要分开。

按图费用：`尝试输出数×适用每图价格＋必要编辑/工具费＋存储/传输`。GPU租用：`实际计费实例小时×当时费率＋启动/准备/idle中被计费部分＋卷/对象存储＋传输/公网费用＋许可/管理`。套餐用“月费＋超出包含额度的费用”，不能把同一包含credit又全部按零售价加一次。比较分母统一为质量达标且按时完成的图，不是模型随便输出的图。

### 17.4 回本、TCO与现金流三张表，不混账

设新增前期现金 `F = 增量整机/升级＋设置部署＋必要网络/存储/供电改造`；各月：

`Cloud_m = 在相同合格产量与SLO下本可发生的云成本（含计划、实例/API、存储、egress、必要管理）`；

`Local_m = 实际增量运行电费＋增量idle电费＋管理员工时×可编辑时薪＋软件/模型许可＋必要网络/冷却/场地＋维护/备份/保险等`。

`月净节省Sm = Cloud_m − Local_m`。

- 仅当需求、单价、产能和Sm近似恒定且 **Sm>0** 时，简化回本 `F/Sm`（月）。Sm≤0显示“该假设下不回本”；超过设备计划可用期显示“窗口内无法回本”。不把残值提前当已经收到的现金。
- 动态现金流用 `累计净额(t)=−F＋Σ1..t Sm−额外更换/扩容现金＋该时点实际假设处置收入`，首次非负是该情景现金回本。延期采购、增长、闲置、云降价/涨价、设备故障/替换都改变曲线。
- TCO曲线比较同周期累计支出；现金口径已计整机购置就不再加折旧。会计折旧另视图，机会成本/资金时间价值可做高级可选，不把它们默默混进简单回本。
- 已有硬件购置是沉没成本；是否出售、额外用电/维护与其他业务被挤占是不同决策成本，明确选择口径。多用一小时的**增量电量**与整机全天电量分开，PSU额定功率不当实测。

UI提议：可编辑假设表＋本地/云/混合三条累计成本曲线、首次交叉月份、利用率/合格率/价格/管理工时滑块与敏感性区间；和任务质量约束下的Pareto并排。显示“哪些参数实测、哪些用户输入、哪些估计、对结果最敏感”，没有真实输入就只显示公式和待填项，**本报告不制作虚构回本月份或实测曲线**。

隐私、地区合规、版权、团队访问控制、数据备份、维护责任、uptime/恢复目标、质量与截止时间独立作为硬门槛，不能用“多花若干元可抵消隐私风险”来合成总分。自托管也需要权限、补丁、隔离和审计；不能因买了卡就承诺安全和SLA。

### 17.5 只验证一套任务，不扩大首版负担

在第十二节访谈中加入一个10人电商团队profile，先收一个真实/获权workflow和一周聚合工作量（不收客户机密prompt或原图）；人工给出本地/云/混合三份**带证据链接和未知项**的计划。保存方案的需求、test IDs、tariff版本和计算假设，之后价格或工作流变更可重算，不能静默改变已分享快照。经过前述Wiki/向导评价，再考虑聊天生成解释；这不是现在部署团队服务或开通云账号。

## 十八、长期路线：时间序列指数、证据社区、用户自测报告与预测

### 18.1 不止今天的卡：云／本地两条时间曲线怎样才可信

可以长期跟踪“相同合格工作越来越便宜／越来越快吗”，但先把统计口径写成公开版本，**本次没有计算实际指数或编造历史点**。

- **固定任务篮子**：文本与图像分开。每个任务固定内容/语言/质量验收、输入输出token及tokenizer、context、并发、cache/连接、reasoning预算；图像固定workflow/model/分辨率/steps/batch等。云与本地按同任务可接受质量比较，不以相同名字认定等价。
- **基期与权重**：只有从获准采集且覆盖足够的一天才设基期`t0`，按真实目标用户任务频率冻结权重`w`，总和1；任何基期“100”只是定义，不是本报告实测值。
- **价格指数**可定义 `100×Σw_i(C_i,t/C_i,t0)`；云用明确的公开list price和另一个可验证的effective price系列（优惠、缓存、Batch、区域条件分开）。本地C为固定假设的全机TCO分摊到合格任务，冻结利用率/电价/管理时薪/折旧或现金口径。币种、FX时点固定，若做通胀调整另列名义/实际系列与来源，不默默混用。
- **性能指数**对相同任务的吞吐或延迟分别定义；例如延迟改善可用`T_i,t0/T_i,t`，但标明越大表示更快；吞吐用自己的方向。TTFT、完成时间、prefill、decode不要混成一个万能性能指数，质量门槛先过。
- **成本性能**优先直接跟踪同合格任务成本/在同SLO下的产能，再考虑有定义的“合格任务吞吐/年化成本”；说明分摊周期。不要把美元/百万token价格指数简单乘GPU tok/s就叫总体性价比。

两条云/本地曲线可以画同一固定任务篮子的单位合格任务成本，但本地利用率必须固定或分情景；用户实际利用率变化的曲线另列，避免把“机器用得更多”误报为技术进步。公开报价日更与实测性能低频更新不同，旧测量不得每天生成假新结果。

另设**frontier指数**：在每个时间点符合相同约束的可买/可用配置中取非劣选择。这允许新品进入，反映“今天最佳可选”，但与固定篮子“同样东西变便宜多少”不同，两个系列不得拼接。新品质量不达标不入选，缺货/退役/无权账号剔除理由公开，避免只留赢家的幸存者偏差。

模型、测试集、权重、硬件可得性或OS变化时建立新版本；如需链式连接，在重叠期按公开规则计算连接因子，同时保留旧版与无重叠时不可接续的断点。报告覆盖率、价格样本/地域、误差、测量日期、预估比例与数据修订，不把补缺预测当历史观测。展示observed / modeled / forecast三层，forecast用虚线和假设，不能把不确定性带当保证。

### 18.2 极简社区投票与“潜力”标签

可用喜欢／不喜欢／值得追踪三种轻反馈选下个任务、发现体验问题；它们是**偏好与选题信号**。投票不改实测速度、价格、证据级别或前沿资格。“Promising”必须写明只是社区期待，不是已验证性能；用户上传真实benchmark才进入审核流程。目标是提出一个可复现schema并逐渐获得社区采用，不能自称已经建立行业标准。

### 18.3 未来agent/skill接入：让用户在自己的系统测，再选择上传

这是未来能力设计，**本次不创建skill、代码、runner或采集任务**。流程应是：用户选择预审测试 → 看资源/预计时间/电量和允许的文件/网络范围 → 明确启动 → 本地生成报告 → 预览脱敏字段/许可 → 另行同意上传。安装、运行、上传三个同意分开，不默认后台运行或递归扫描电脑。

报告schema拟包括协议/runner版本、任务hash、模型来源/revision/artifact hash、quant与KV精度、runtime/flags、OS/kernel/驱动、GPU/VRAM/CPU/RAM、context/输入输出计数/batch/concurrency、cache/冷暖、各阶段时间定义和重复样本、功率测量来源/频率/是否wall、失败/OOM及provenance。只上传获准的原始数值摘要或可审计日志hash，不默认传prompt、输出、客户素材、路径、用户名、IP、主机名、序列号、凭据或完整系统日志。

固定签名只能证明“这个提交没被改过／来自某密钥”，不证明硬件真实、计时未伪造。保留reference-lab／可复现社区／未验证三层，测试全序列和失败而非只报最快一次；去重报告hash、重复数据来源、异常审查、跨提交一致性、人工复跑/独立审计。Sybil与挑选结果不能只靠“一人一票”解决，也不能为反作弊而无限收集身份。涉及奖励时另做隐私/合规与刷量评估。

安全仍是白名单workflow和依赖、非特权隔离、CPU/GPU/时间/磁盘/网络上限、可中止、清理策略与明确启动。不要在用户电脑或站方机器自动运行陌生自定义节点/插件，不默认容器能防所有问题。用户不上传仍应可在本地看报告。

### 18.4 “Kelsey”／Polymarket：只作远期概念，不是市场验证或MVP

用户口述“Kelsey”具体平台**未确认**，可能指Kalshi，但不代他定名。以下是对Kalshi与Polymarket官方资料的概念核查，不是开户、发起市场、下注或推荐参与。

- **Kalshi**官方说用户可提议，由市场团队审查合规、可操纵性与需求，不能保证上线；每市场规则规定结果来源和结算条件。[44] CFTC官方说明指定交易所可按规则提交self-certification，不是每一市场都等于事先获CFTC逐项批准。[45] 本次实际读取的Member Agreement §VI将**People’s Republic of China列为Event Contracts交易受限地区**；非交易访问/会员有不同条款，也不能由此推定Tony可交易或可获例外。地区、主体、产品和当时规则都须核实，不提供规避方案。[44]
- **Polymarket**官方说明市场由市场团队创建，用户只能建议；本文核实的帮助页描述按预先规则、使用UMA optimistic oracle及争议流程，不是上传一个指数就能自动开盘。[46] 开发文档有地域限制、KYC/合规条件，且不同产品/司法辖区并不相同；API可访问或某地未列在一张限制表上**不等于当地法律许可交易**。本次未核实Tony个人资格，不调用地理IP端点、不注册/提交/充值/交易。

如果以本站自己编的价格/性能指数结算资金，站方既能改采样、权重、数据缺失处理、发布时间和修订，又可能影响输赢，这是**oracle操纵与利益冲突**，绝不是把钱押上就更科学。即使预测平台批准，也至少需要：预先冻结独立公开方法/篮子/基期/数据截止与时区；可验证公共快照/签名；独立计算和外部resolver；纠错窗口、源失效/模型退役/改价边界规则；数据知情人员的访问/交易限制与利益披露；异常市场激励审查。不能保证这些设计足以获平台或监管接受。

预测概率是参与者在流动性、激励和规则下的判断，**不是真实benchmark、不替代证据、不等于用户愿意为网站付费**。先做无现金的可校准预测：对事先定义、能独立判定的未来成本/任务性能事件记录概率、截止、理由和事后Brier score/校准图，保留失败预测；仍与测量库分层。真钱市场不应成为核心商业要求、MVP依赖或所谓“验证需求”的依据。

### 18.5 范围总闸：新增的是路线图，不是本轮全部开工

本轮仍只交研究笔记。未来若执行，先是人工建议＋受限参考表＋短Wiki/向导，证明需求；再小范围受控测试，才考虑自托管聊天；之后才谈一个团队回本case的产品化、低频指数、用户自测上传。全设备库、全云实时跑分、四源每日历史、通用agent与真钱预测都不在首个4–6周承诺里。**最小可证实决策价值，比最大全景图更重要。**

## 十九、动态可视化探索与换肤：把同一套证据变成不同深度的界面

> 以下是Tony提出的Footprint Network风格探索体验的**产品设计建议**，不是对Footprint Network现有功能的审计，也不推断Tony过往项目采用过哪些技术、实现或商业结果。本节不创建界面、图表或可执行查询。

### 19.1 联动探索：从一张推荐卡到可复算的视图

在已匹配的任务/质量/context/地区/日期范围内，让筛选器、表格与图表共享同一个显式状态：

- 在价格—性能散点圈选一组配置（linked brushing），同步高亮侧边对比表、显存/价格分布和对应趋势；先高亮还是实际过滤要清楚区分，可撤销并展示当前筛选条件。
- 点选卡型、VRAM、新旧、runtime、模型artifact或预算范围时，其他图与表联动；切换指标时保留合法条件，不兼容的组合解释原因，不偷偷扩大样本以补满画面。
- **指标选择器（metric picker）**分别列模型能力、实测硬件表现、价格/TCO、任务合格率、社区偏好；显示单位、方向、样本数、测量/估计状态和来源日期。不能把Arena、AA、tok/s与点赞变成同一可替换“得分”。
- 默认展示当前cohort与排除原因；未知不画成零，稀疏数据提示覆盖不足，排序/轴截断/对数刻度明确标识。Pareto遵守第五节与第十五节任务和质量门槛，不因换个轴就生成跨任务“斩杀线”。

**自然语言入口**可以把“给我看中国二手24GB卡，在这套商品图任务下预算内的回本比较”转成需求候选，再由受控schema验证、向用户展示并确认。缺数据时返回可用视图或澄清，不能用LLM生成伪数据填图。

### 19.2 视图spec，而不是让聊天生成SQL/JS

保存的是**声明式、经校验的view spec**，字段可包括schema版本、task/cohort ID、可用实体过滤条件、指标ID/单位、聚合/分组白名单、图表类型、轴范围、排序、布局、预算假设、source/test/tariff快照版本及生成时间。自然语言只能映射到允许的枚举与有边界的参数；服务端执行白名单只读查询模板、确定性计算和行数/时间限制，**不执行任意生成的SQL、JavaScript或表达式代码**。原始prompt/检索文档也不能借视图配置注入可执行指令。

保存/分享应区分：①固定快照，证据和计算版本冻结便于复现；②“使用最新数据”的动态视图，明确标识随数据变化并保留修订记录。分享前预览内容和权限，私有预算、团队需求、用户身份不默认放进URL、公开索引或公共缓存；可访问链接不等于取得原始数据再分发许可。没有数据保存权时只保存允许的引用和参数，不借快照绕过来源许可。被撤权或失效的证据要提示不能完整复现，不能静默替换。

### 19.3 新手／专家深度，与亮／暗／二次元主题正交

“新手推荐卡—解释—专家证据表”决定信息深度；light/dark/二次元换肤只决定视觉表现，用户可任意组合。**同一需求、证据与计算版本，推荐事实、真值、分数、置信度、成本和排名保持一致**，不因皮肤、人物偏好或商业主题变更。

使用design tokens管理色彩/字重/间距/图表语义，人物与背景只用原创或已核实授权素材，不借用动漫IP、商标或未经许可图像。状态同时用文字/形状表达，不靠红绿或夸张动效传递结论；满足可读对比、键盘操作与可见焦点、屏幕阅读器表格替代，支持移动端触控、低端设备简化渲染和reduced-motion。主题不能遮住单位、风险、缺失值或来源。

个性化推荐偏好、默认指标、预算和主题都应**opt-in、可查看/编辑/重置/删除**；不根据浏览习惯暗自推断收入或工作单位。匿名默认可本地记主题，跨设备保存另说明数据用途；更换主题不要求交出更多个人资料。

### 19.4 有边界的MVP

只做2–3种图＋一个指标选择器＋少量预设：成本/性能散点、按需价格历史线、团队累计成本/回本曲线；在数据尚不具备时只提供模板/历史可用范围，不造点。先做联动筛选与表格，再考虑自然语言转spec和版本化分享；**不做通用BI画布、拖拽公式语言或无限制自然语言数据库Agent**。亮/暗主题可先行，二次元皮肤在核心可用性与素材许可验证后作为可选，不挤占证据质量预算。

## 二十、现在买还是等：新闻辅助的GPU价格预测，不是预测市场

> 这是**独立于第十八节Kalshi/Polymarket概念**的选型辅助设计：预测某一可比GPU价格分布、等待风险及其对回本的影响。本节没有预测任何实际价格、推荐Tony现在购买、启动监控或制作已运行的预测器。

### 20.1 先有合法且可比的历史，再谈未来

基础仍是第六、七节价格口径与来源权利：获得历史保存/统计/展示许可的SKU与VRAM、地区/币种、新旧/翻新、卖家类型、库存、含税运费和促销资格分别成系列；listing/报价与已成交不能混成同一label。不能把同GPU芯片不同板卡、全球最低变体价或缺货价变化误当降价。保存观测时间、抓取/导入时间、当时可得的数据版本、去重/异常与缺失标识，给出样本量及覆盖变化。

新品无长历史、二手卡稀疏、来源许可不足或促销不可复现时，先**拒绝数值预测**，只给已验证事件与未知项。未经许可不购买/抓取历史库；过去没有采样就不靠LLM补造旧报价。

### 20.2 新闻提事件，统计模型给分布：各自不越权

可研究的信号包括新品发布/实际开售、产能与供需、库存、汇率、出口政策、停产/EOL、季节性促销及替代卡上市；它们只是**待回测的假设**，不是已证明的价格因果关系。新闻热度可能滞后于价格，也可能重复传闻；需要官方公告或独立可核实来源、来源权利与置信度，不把转载数量当独立证据。

LLM只辅助结构化抽取“事件、涉及产品/地区、生效时间、来源链接、首次公开可用时间与矛盾信息”，人工/规则验证。记录**当时公众何时能看到该消息**，以及本站何时获取；事件发生日不等于预测者能提前知道的日期。后续更正另存，不能把今天完善的文章回填成过去已知。

数值预测必须来自有版本、输入特征、训练窗口和评估结果的统计/时序方法；LLM不得凭新闻措辞编出“30天后跌12%”。拟议7/30/90天预测分别给中位数/可解释分位区间、相对当前价格的降价概率与事先定义的降价阈值，说明区间覆盖目标、适用系列和模型条件；这些是产品字段设计，**不是本报告已算出的概率或价格**。时域越长通常面临更多变更风险，不能默认同一误差带适用全部时域。

### 20.3 滚动回测与拒答门槛

用rolling-origin历史回测：每个预测原点只使用当时已经取得且可合法使用的价格与新闻版本，以未来7/30/90天相同定义价格为label。训练/调参/阈值选择都留在过去窗口，留出最终out-of-sample时段；窗口重叠的相关性与统计区间需要说明，不能把随机打散价格序列当独立测试。

先比较**价格不变基线（no-change）**，再考虑简单移动/季节方法，最后才研究事件特征是否有增量。评估分horizon、SKU、地区、新旧与市场阶段：中位/点预测MAE、方向/降价概率的calibration与Brier score、预测区间coverage与宽度（必要时分位损失）；避免以少数暴跌样本证明普遍有效。不能只报平均误差掩盖新品、政策突变和低样本失效。

明确阻断泄漏：未来FX/实际供货、后修新闻、未来促销、全时段拟合的去异常阈值、今天重建的卖家存活集合都不能进入过去预测；预处理与缺失处理也要在各训练窗口内拟合。新SKU/结构性断点、数据中断、样本不足或未优于基线时，显示“暂无可靠预测”，保留失败回测，不保证必能择时或省钱。

### 20.4 预测如何进入选型与回本，而不替用户下注

图上严格分observed历史实线、forecast虚线及区间、随后observed的新数据点；保留每个预测原点的旧forecast，不用新预测覆盖错误历史。可叠加经过验证且带来源/公开时间的事件标记，避免把贴在曲线附近的新闻视觉暗示为因果。

“现在买／等待”对比把未来价格分布作为**TCO/回本敏感性输入**，而非保证：等待期间继续用云的费用、已知项目延期/产能损失、现有机器可用性、质量/SLO、缺货与保修风险、现金约束均可编辑。不可验证的机会损失显示未知，不凭空给营业收入。隐私/地区/截止时间等硬约束可能排除等待或云，不被降价概率抵消。

### 20.5 MVP止于历史与核实事件

第一版只展示有权使用的历史趋势＋经过核实的事件时间线及“数据不足”的解释；待积累足够历史、验证许可、通过无泄漏回测并展示out-of-sample增益后，才考虑7/30/90天数值预测。没有这些条件就继续历史视图，不把第十八节预测市场概率当价格预测器的真值或捷径。本节不新增任何实际日更采集、通知或定时任务。

## 二十一、多渠道传播：从可复现的数据问题到内容，再回到知识库

> X、相关社区、网站、TikTok、YouTube Shorts及长视频是可选传播渠道，以下只是策略和编辑流程；没有发布、开户、联动账号或设置自动发帖。

### 21.1 一次证据产出，多种表达，不是到处复制一条广告

推荐链路：**数据事件／用户问题 → 核实来源、时间、口径与使用权 → 人类编辑审批 → 平台适配的图表/文字/短视频 → 回链可复现的saved view或Wiki → 收集纠错与后续测量问题**。编辑审批针对即将发出的正文、图像、链接与平台，不以“批准内容策略”替代每次实际发布授权；自动发现只进内部待审队列，不直接发出去。

- 网站是主档：保留完整测试环境、失败/OOM、计算假设、来源、版本和更正。分享视图按第十九节权限与快照规则处理，匿名公开案例不得暴露团队预算、客户素材或私人对话。
- X适合一张图＋一个可限定的结论/问题，标数据日期、适用任务和主要未知项；线程可以补方法，但不把短文案写成“所有场景最强”。
- 相关Discord/论坛等社区先遵守频道规则与利益披露，用具体复现问题和失败案例请求反馈，不跨群刷屏，不未经许可私信拉人，也不把私有讨论复制出圈。
- TikTok与YouTube Shorts用竖屏字幕、清楚单位、必要方法/风险提示讲一个问题，例如“同卡长context为什么先OOM”“10人团队为什么不等于10张卡”；视频描述或落地页链接完整证据，不靠快切遮住不确定性。
- YouTube长视频可解释工作流、安装/维护、云本地质量对齐与回本敏感性；Shorts是入口，不替代方法。图表/素材/音乐/配音与新闻截图分别核对授权，数据可引用不等于视频画面可搬运。

### 21.2 更值得持续做的选题

实际任务成本与合格率、相同工作流的本地/云/混合差异、回本对利用率和管理工时有多敏感、context/prefill等待、测试失败与纠错、热门推荐为何不适用某用户，均比泛泛“本周最强卡”更贴近决策。仅在有证据时才报道价格变动；小样本/预测/厂商自述需显眼区分。

不承诺“简单、低成本、必爆、病毒式增长”，不把曝光当商业需求，也不能靠耸动降价预测制造紧迫感。赞助/affiliate若未来使用，要披露利益关系，编辑选题与测试判定保持独立；不因高佣金影响排序。

### 21.3 衡量合格行为，而不只看播放量

关注带任务意图的qualified traffic、完成需求向导比例、有效保存比较/计划、重复使用与重新计算、阅读方法后能否作出决定、有效纠错/可复现提交与审核通过情况。按渠道看这些下游行为与编辑成本；点赞、浏览、完播可作上游诊断，不单独证明选型价值或付费意愿。分析应最小化标识、说明目的，尊重拒绝追踪，不为归因建立跨平台个人画像。

首轮只选**网站主档＋1–2个实际可持续的外部渠道**，例如YouTube与一个目标社区；X、TikTok、Shorts按同一主题的小样本实验逐步加，不同时承诺五条内容流水线。若短视频流量很大却不带来合格比较或复用，调整题材/落地页或停止，不用扩大发帖量掩盖。

### 21.4 与前述MVP的范围映射

| 阶段 | 原有核心 | 本轮补充边界 |
|---|---|---|
| 需求验证／MVP-0 | 人工配置卡、小参考表、短Wiki、静态向导、一个团队case | 用2–3种受控图、指标选择器和少量预设解释已有证据；价格仅已有合法历史与核实事件；网站＋1–2个外部渠道的人工编辑实验 |
| 有可靠数据后的MVP-1候选 | 受限参考测试、条件式TCO/回本、自托管聊天离线评价 | 再评估联动筛选、声明式view spec与确认/分享流程；个性化opt-in；聊天仍不得生成执行SQL/JS |
| 通过验证后的MVP-2／长期 | 可审计聊天、低频指数、社区自测与许可内的价格覆盖 | 自然语言视图、更多主题/二次元换肤、预测器和渠道扩展逐项验证；数值预测须通过回测与样本外检验，不承诺同时交付 |
| 非本轮／非核心依赖 | 第十八节保留的用户runner、行业schema愿景和预测市场概念 | 不建立任意BI builder、不运行collector/自动发帖、不设监控、不交易；前述指数、报告与市场章节完整保留，价格预测与真钱市场互不替代 |

**三节追加的执行边界**：全部为产品设计与验证计划，未实现主题/视图/预测器、未采集新闻或价格、未回测、未生成实际预测、未发帖、未安排自动化。现有价格表和第十五至十八节内容保持不变。

## 二十二、开放研究层：知识库／数据库通过只读MCP进入外部Harness

**愿景可以更大：网站是权威维护的canonical知识与证据层，不必把所有研究都锁在本站聊天。** 用户可让兼容的外部agent harness/runtime调用，再与自己掌握的数据研究；Harness在这里是通称，**不是特指同名商业CI/CD厂商**。Tony提到“先用Typeface”，其具体含义尚未确认，仅保留意向，不推定工具、技术栈或安装授权。

### 22.1 官方协议能支持什么，不能保证什么

本次读取MCP官方规范：Resources通过URI提供上下文，由host决定如何使用；Tools提供可发现的功能，`inputSchema`声明输入，`outputSchema`可约束`structuredContent`，不等于LLM自行生成可靠事实。标准transport包括本地子进程stdio与远程Streamable HTTP；HTTP授权规范采用OAuth机制，协议授权是可选项，但私有数据服务仍必须落实鉴权。[47–51]

协议版本、能力声明、transport、授权和客户端UI支持可能不同；**不能承诺“任何Harness即插即用”**。先定义支持范围，未来再公布已测试的client/version/protocol/capability矩阵；调用和上下文拼接由客户端策略决定。`latest`文档会变，实施时固定规范版本，不把本次阅读当兼容性实测。

### 22.2 拟议接口与证据契约（仅概念，不是已有API）

| 只读能力 | 输入／输出约束 |
|---|---|
| 搜索Wiki与证据 | 关键词、实体、版本和权限范围 → 审阅revision、来源片段及citation IDs |
| 列配置覆盖、受控比较 | hardware/model/artifact/runtime与workload条件 → 已测/缺失配置、匹配条件与排除原因 |
| 查历史价格／指数 | SKU、地区、新旧、币种、as-of及vintage → 当时可知观测/指数方法版本，不能悄悄换最新修订 |
| 成本／回本计算 | 经验证的任务量、费率版本、TCO假设 → 确定性计算及敏感性、未知项；不执行交易 |
| 读取许可内报告 | 指定视图/报告版本 → 可复现摘要及引用；限制导出数量、字段与用途 |

所有结果携带来源、test/price IDs、版本、时间、单位、任务质量门槛、context/quant等条件、样本覆盖/缺失、证据等级/不确定性、许可及复现参数。事件时间、首次公开时间、本站取得时间、修订时间分开；保留as-known快照，不能让外部研究误用未来信息。

### 22.3 开放接口不等于开放所有数据

MCP不消除AA等来源的竞争/再分发限制：只返回获准数据、本站原创测量或允许的引用/摘要；付费访问也不自动获得转售权。分页、配额、速率限制、字段级scopes与可能的付费层是**商业假设**，需验证授权及付费意愿，不保证能收费或无限导出。

租户ACL、明示同意、最小化查询/日志、撤权、隔离缓存与结果权限检查不能省；检索内容及tool描述可能恶意，按数据处理，不接受其指令。服务端只用白名单只读查询和calculator，**无任意SQL/代码、写库、开户或交易API**；“read-only”标记不能替代实际权限控制。

外部客户端默认在其受控环境结合私有公司/组合数据，**本站不要求上传这些数据**；host若使用云模型，用户仍须核对其外发与留存。任何必要上传另行预览、最小化并同意，不能因接入MCP就默认授权。外部MCP是“别人取本站证据”，区别于第十六节“本站RAG使用资料”与用户自带LLM/BYOLLM；三者不要求一起部署。

先给许可内的版本化下载数据或人工报告，验证研究需求，再试受限MCP接口。真正差异化是**证据网络、分发、复现与持续维护**，不是挂一个MCP标签。本节不开发server/schema代码、不安装插件、不连接服务。

## 二十三、AI投资观察层：从技术成本事实提出问题，不直接变成股票结论

这可以成为有意义的**投资研究假设入口**：个人选配置、团队算回本、研究者组合证据、投资观察者追踪行业机制；不是把长期愿景全部塞进MVP，也不提供具体证券建议、目标价或交易。

### 23.1 每个研究问题都附竞争解释与失效条件

| 观察问题 | 可观察证据／替代解释／何时应推翻 |
|---|---|
| 质量匹配的推理成本是否下降？ | 固定任务成本指数；缓存、促销或篮子变化也能造成下降；跨版本质量失配则不能下结论 |
| 云／本地交叉点是否改变？ | 同SLO的TCO与利用率敏感性；云降价、管理工时和需求峰谷都是解释；未过隐私/质量门槛的便宜方案无效 |
| VRAM／带宽瓶颈如何变化？ | context、prefill/decode、OOM与runtime对照；软件优化或量化也能改善；缺少受控测试不能归因硬件需求 |
| 效率、Edge采用意味着什么？ | 复现测量、兼容和可信采用数据；效率可能降低每任务硬件需求，也可能因降价产生rebound、扩大总需求；仅下载/点赞不是部署量 |

用户总成本下降**不等于芯片厂利润下降**。零售listing与众包跑分有选择偏差，不能据此推断GPU供给、行业利用率、销量、收入或厂商毛利；这些结论必须另有独立、获权的行业/财务证据。软件、硬件、云服务商的价值获取也可能不同，保留反向解释。

### 23.2 与金融数据连接，需要第二条证据链

公司/ticker/产品映射标来源、日期与覆盖，区分母子公司、供应商/客户和业务暴露，不能见到品牌就自动映射整家公司收入。财报按财政年度/季度、公告可得时间、滞后、币种与修订对齐，核对金融数据许可；缺失与退市样本不得删除来美化结果。若研究收益关联，另处理复权/分红/拆并股等corporate actions、存活与选样偏差、交易成本及样本外检验。

沿用不可覆盖的指数方法版本和vintage/as-known快照；回测只能用当时已公开数据，不能拿后来修订的指数或财报预测过去收益。公开信息也不代表可无限转载；不收集/推送MNPI，利益冲突、持仓/赞助关系须披露，投资研究分发、数据许可与当地合规要求另核实。禁止把市场预测概率、热度或本站赞助商当作技术事实。

## 二十四、公开知识与数据仓库：一个证据底座，多个Access入口

> **设计提案，未创建或公开仓库。** Tony提出网站信息也可放进GitHub Repo，让更多人访问和复用。可以把它视为网站、只读MCP、公开GitHub仓库与下载版本四种入口，而非四套相互漂移的数据库：共用canonical实体/证据ID、schema、引用与release/vintage；页面和MCP报告所用版本、更新时间、覆盖及稳定来源URL。

### 24.1 开放什么，先把许可分层

候选公开内容是本站原创Wiki、方法、配置说明、schema、可复现测试定义，以及**自有或明确获准再分发**的benchmark数据；未来软件代码单独管理。数据可见、公开Repo、允许fork都**不自动等于取得开源/开放数据许可**。代码可评估MIT/Apache-2.0，文档可评估CC BY 4.0，数据按权属、数据库权与来源条件评估CC BY或合适数据库许可；这些只是待审选项，不是已经授予的权利或法律结论，不能用根目录一份LICENSE覆盖不兼容来源。

每份数据保留provenance、来源/日期、许可和字段限制，要求贡献者确认其贡献及再许可权；不收用户身份、凭据、私有prompt、公司数据或未授权客户素材。AA、marketplace价格、新闻等不因入库/MCP而可再分发；禁发raw data只在许可允许时留下metadata、引用/链接，否则不纳入公开包。

### 24.2 仓库结构与可复现发布

假想目录：`wiki/`放Markdown，`schemas/`放JSON Schema，`methods/`放测试/指数方法与配置，`data/`仅放获权的小型JSON/CSV，`rights/`放来源权利与citations，`releases/`放manifest，另有README、CHANGELOG和贡献指南；较大Parquet可在许可内作下载产物，不把实时数据库整体塞进Git。

每次release manifest固定schema版本、数据vintage、方法版本、生成时间、文件hash和覆盖范围，让研究者clone/fork、锁定版本并在自己环境join私有数据。纠错发新release并关联旧版，不能悄悄覆盖历史；签名/provenance仅证明出处或完整性，不证明测量真实。另设撤权、隐私删除及失效数据通知规则；若法律/安全要求删除，需说明复现断点，不能为“不可变”承诺继续保留违法内容。

大量每日价格历史留在**具备历史保存/再分发权**的版本化object store，仓库只存许可内manifest/摘要与release pointers，避免Git无限膨胀。GitHub不是数据库查询SLA，也不是唯一备份；网站/MCP可做在线索引，但必须说明与发布快照的时差，稳定链接不可无提示改指别的vintage。

### 24.3 社区协作与公开前闸门

用Issue模板收纠错、缺失覆盖和复现请求；PR须做schema校验、来源/权利审阅与必要参考复测，**不自动执行提交者的workflow、脚本或插件**。公开路线图、维护者/贡献者角色、审阅责任、兼容与release文档；接受fork和不同意见，清楚区分官方发布、社区分支及未验证提交，不承诺无限维护所有分叉。

未来公开导出必须从**curated allowlist**生成，先做安全扫描、隐私/脱敏与人工权利审查；公开Git历史被复制后很难撤回，删除一个文件不等于回收已有clone。**绝不将现有私有`tony88331/obsidian-vault`改为公开，也不整体复制其内容**。本次只是把方案保存在现有私有研究笔记，用户提出愿景不等于批准建库、发布或修改可见性。

### 25.3 local.ai：需要正面对标的不是图表，而是它的任务定义

#### 身份与独立性

[About](https://local.ai/about)明确写“Independent reference”，底层速度和evaluation由**Exo Labs**产生，并声明与列出的硬件厂商／模型提供方没有商业关系。这能确认数据生产关系和其公开立场，**不能直接推断域名所有权、法定运营主体、投资关系或没有任何利益冲突**。本次页面未提供足够信息核实这些事项，也未做WHOIS或隐私身份追踪。

不要将其混为LocalAI开源推理API软件，也不要把“使用本地模型”本身当成local.ai网站的独有技术。

#### 比较单元与指数

页面明确列出六层：Model × Harness × Hardware × Inference engine × Configuration × Model variation。它不是只给一个模型挂上GPU理论速度。

- 自有Intelligence Index默认 **2% τ²-bench＋36% GAIA＋62% GDPval**，不是Artificial Analysis的同名指数。
- 缺任何一项完成结果就不生成总指数，不补零、不重分权重；每个精确模型variation取**best completed measured run**。
- 每个evaluation的median end-to-end任务时间沿用相同权重，转为typical task／Tasks per Hour，配硬件成本形成Value Index。
- About称用户可在chart settings修改权重，图表／表格实时重排；**设置入口在浏览器中可见，但未能进入或修改，实时重排未实际验证**。
- 用接近decode速度而任务完成时间不同、显卡规格不直接预测任务时间、不同量化能力不单调三个例子说明其立场。数字是站方测试，不应据此宣布某硬件普遍优胜。

**对原平台的影响（分析）：** 原本“质量—时间—成本三维”“精确量化评测”“不同任务可调权重”“缺失不冒充零”等不仅是好规范，也是已有竞品主张。网站必须在具体用户任务、中文可解释证据与本地采购／团队成本上证明增益，而不是复刻一套漂亮三维图。

### 25.4 lcz.me：适合学问题和运营机制，不适合直接搬成数据库

#### 它到底是什么、谁在维护

[关于页](https://lcz.me/site/about)自称开放、自由AI交流社区，讨论范围从硬件、模型、推理到应用。[上线帖](https://lcz.me/topic/2)由`terry`发出，帖内签名反复链接“抡锤者”YouTube；[规范公告](https://lcz.me/topic/1777)中terry自称站长。因此可以说“公开可见的站长为terry、论坛与同名YouTube账号存在公开关联”，**不能据此补造公司实体、真实姓名、注册地或股权信息**。上线日期的时间字段抓取缺失，不采用搜索摘要给的具体日子。

#### 有价值的不是一个平均tok/s，而是具体失败条件

[topic/2174](https://lcz.me/topic/2174)作者报告R9700 32GB、Ryzen 7 9700X、64GB RAM、Strata v0.1.40，对两种量化做能力与速度对照，披露KV、speculation、功耗墙、同题序及测试集。作者称4700+请求，约240万输出token；这些是作者自报，**不是本站独立验证**。评论有用户讨论agent中的实际表现和自己的切换体验，是定性需求信号，而非部署规模调查。

**重要方法审阅：** 帖子同时写，两种量化分别采用low-RAM与RAM-budget加载方式，体积也不同；作者称“同参数”，但实际系统配置并非只有量化bit一个变量。所以其结果可被描述为“这台机器上的两套量化／加载组合表现”，不能净归因为“3-bit天生比4-bit强”。少量题目、单轮工具调用、不同子任务与p值也不能直接汇成全局能力结论。**本段是对公开方法的分析，不是重新统计原始日志。**

这恰好验证平台应记录：量化文件ID／hash、专家驻留与offload、RAM／SSD读取、KV格式、context、speculation、harness和能力评测方式，而非只存模型名＋显存＋tok/s。

#### 可借鉴的社区增长方式与边界

- 上线帖中有用户自述从YouTube看视频而来，证明**至少有个案的视频→论坛迁移**，不证明高转化率，也未核实频道订阅量或视频观看量。
- 公告强调原创、真人讨论，拒绝直接AI发帖回帖（允许整理格式），并明确标识管理助手是例外。对原第二十一节渠道计划的具体修订是：**不要用agent自动往这个论坛批量发“有价值内容”或导流**；将来若参与，需真人复核、遵守其当时规则且另获发送授权。
- 社区原帖可作为“用户问题／可复现请求”线索；若要把完整测试搬进公开GitHub／MCP，应先取得作者对相应文本、日志、图表、数据的权利确认。站点开放阅读、技术上可能有论坛API，不等于官方许可抓取／再分发。
- 搜索命中的[topic/2303](https://lcz.me/topic/2303)在本次返回中出现**已删除主题提示**。即使提取器仍返回部分文字，也不将其当稳定公开来源或导入知识库；只记录链接失效／状态风险。此例支持保留失效与撤回状态，而非永久镜像一切。

### 25.8 第一切口、内容渠道与“不做清单”

**在原10–12次访谈内收紧实验，不另增建设项目：** 让有一台明确Mac／消费GPU的中文营销或电商小团队提交一个脱敏、允许用于研究的真实文本任务；人工并排展示“保留现机本地／云API／升级硬件”三张建议卡。每卡只有：合格标准、资料长度和敏感性、每月任务量、允许等待时间、来源及配置、未知项、成本范围和工时假设。缺真实测量就写需验证，不生成装作实测的排名。

- **质量先于回本：** 达不到中文任务最低标准的低价方案直接排除；不把AA英文总分当中文营销验收。
- **成本按同工作量与同SLO：** 云端区分缓存／输出／峰值，本地区分购入价与可避免现金成本、已有硬件、残值、电力、运维、返工及排队；给利用率敏感性，不给“一定几个月回本”。
- **成功信号是决策改变而非点赞：** 记录用户原方案、现用替代工具、未解问题、建议后是否有明确下一步和是否愿意为后续人工验证付费。访谈样本不拿来宣称市场份额。
- **SEO用长尾证据页而非批量造词：** 借鉴LLMCheck的“数据页＋方法页＋可链接对比”、llm-speed的run永久链接。优先“这台具体Mac、这段上下文、这类中文任务为什么不能给一个tok/s”的实证内容，不做几千页没有对应测量的GPU×模型组合SEO。
- **视频带回证据，不只带回聊天群：** LCZ公开个案说明YouTube可把内容受众带入讨论；每篇视频或短内容对应可引用的方法／配置卡，标已测与估计、提供纠错入口。不能从一个帖子推算获客成本。
- **社区不拿自动化代替信任：** 不自动向LCZ、Reddit或X投放研究，不拿别站真人回复训练“社区人格”；先维护原有内容和证据，再判断有没有必要另建社区。

**明确不建议先做：** 通用GPU大榜、全站镜像抓取、无权利审查的数据聚合MCP、自己的通用测速标准、为跑分先买硬件、没有质量验证的总分、假实时价格指数、GPU价格预测／下注、把LLM tok/s换算成ComfyUI产能、为了有聊天就做无边界agent顾问。

## 二十六、llmfit 的 MIT 许可：哪些资料可直接用于商业网站

> 核查日期：2026-11-20，Asia/Shanghai（中国标准时间 UTC+8）。本节只核查许可、数据字段和来源声明，没有运行、安装、构建llmfit，没有对外发布数据库。固定核查版本：[`26450cccaf3a3f14b1822875f2473847a744a718`](https://github.com/AlexsJones/llmfit/commit/26450cccaf3a3f14b1822875f2473847a744a718)。该提交时间为2026-11-18 22:59:13（Asia/Shanghai），提交说明为每周benchmark cache刷新。

### 26.1 直接回答：可以用，但分清自己的数据与上游缓存

**可以把llmfit自身维护的模型目录、适配规则、估算方法和贡献数据，用作商业网站的基础，复制到自己的数据库并修改；不用因此把整个网站开源。** 依据不只是首页MIT徽章：根目录[LICENSE](https://github.com/AlexsJones/llmfit/blob/26450cccaf3a3f14b1822875f2473847a744a718/LICENSE)明确允许使用、复制、修改、发布、分发、再许可及出售；[CONTRIBUTING.md末节](https://github.com/AlexsJones/llmfit/blob/26450cccaf3a3f14b1822875f2473847a744a718/CONTRIBUTING.md#license)明确贡献按MIT授权。根目录版权为 **Copyright (c) 2026 Alex Jones**。

条件是保留完整版权及MIT许可声明；实务上在导入快照／分发包保留LICENSE，并在网站Third-party notices提供完整声明、来源和版本。MIT不是copyleft，不要求整站采用MIT、开放源代码或免费提供服务。其免责条款也应保留。

**本次没有发现单独排除data目录的许可声明，不能因此把整个目录判为不可用。** 但根许可称Software及associated documentation，未另外逐一授予第三方数据权利；对已有明确外部来源的缓存，应按具体来源区分，而不是把所有内容一概改标“我们拥有的MIT数据”。这不是所有数据不能用，而是少数来源需要更精确的许可判断。

### 26.3 三种“直接用在网页”不是同一件事

1. **导入固定版本到自有数据库：推荐。** 对可复用部分保留commit、路径、来源、license、取得时间和变化记录；把完整MIT notice随快照保存，在网站Third-party notices展示。站内可修改、筛选、商业收费，不需开源整站。若未来刷新，只同步审核允许的字段，别顺带把LocalMaxxing完整缓存也无条件公开。
2. **直接让访客浏览器请求raw GitHub或live API：许可上不等于另加禁令，但运营上不建议当生产数据库。** MIT没有承诺GitHub或上游API的可用性、配额、CORS或字段稳定；固定commit避免内容漂移也不等于服务SLA。llmfit README确实提供自托管REST endpoints，但仓库公开不等于作者运营了一个可供网站无限调用的公共实例。此次没有实测CORS／API配额，不编造具体限制。
3. **网页自动检测访客硬件：不是复制JSON就能得到。** 文档的检测依赖本机`nvidia-smi`、`rocm-smi`、`system_profiler`等原生系统能力。普通网页不因此获得这些权限；在服务器运行检测得到的是服务器硬件，而非访客电脑。可先让用户手填／选择hardware profile；未来如需本机辅助工具，应另行设计并获授权，当前未安装任何工具。

### 26.4 对现有平台研究的实际修订

原第六／二十五节“llmfit数据权利应分别核实”的原则保留，但结论应更具体：**不必等到全生态所有权利问题都解决，才复用llmfit自身的目录、方法及已按MIT贡献的数据。** 可以优先采用这些内容，保留版权／许可与来源，减少重复造fit规则；只将有明确不同来源且授权未覆盖拟议用途的部分列为条件项。

目前最明确的来源缺口是 **LocalMaxxing缓存的第三方整库再分发范围**，不是MIT禁止商业网站。LocalMaxxing[官方API文档](https://localmaxxing.com/en/api-docs)明确支持partner／agent／developer查询；其[Terms of use](https://www.localmaxxing.com/en/terms)（页面标2026-10-04更新）明确用户保有内容所有权、平台源码MIT，没有给出统一开放数据许可。这里不认定所有数字都构成受保护作品，也不作全球数据库权的笼统法律结论；若要商业批量镜像，需针对实际字段和分发方式澄清，而不是靠llmfit根LICENSE替上游授权。

**最小合规行动建议：** 先确定一个固定commit的允许字段快照＋完整MIT notice＋provenance；分别展示estimated、calibrated、community measured；保留模型原license字段和HF链接；不托管模型权重、不冒充官方背书、不宣称所有组合均为benchmark；对LocalMaxxing缓存暂不做无条件全量再分发。本次没有发布、联系作者或创建issue。
